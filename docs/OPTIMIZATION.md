# 展会实时链路优化与验收（2026-10-15）

目标是减少用户开始体验和连续换装中重复发生的等待。方案沿用 Openbuy 已验证的参考素材提前上传、按内容和账号复用、连续连接更新条件策略，针对 Miror 的展会状态、独立镜账号、Web 和 Android 生命周期重新接入。

## 实现

| 环节 | 行为 |
| --- | --- |
| 固定素材 | 素材保存后自动向两个已配置服务上传参考图 bytes，保留 MIME 与透明通道，持久保存供应商引用。相同内容、MIME、账号和区域复用；原素材仍是恢复来源。 |
| 开始体验 | 读取已发布快照和后端 binding，校验内容与账号；未就绪不启动生成，Web 与原生 Android 均不回退 SDK 上传。准备不会提前开 RTC 或签发临时 key。 |
| 连续换装 | Web 与 Android 同模式摄像头体验保持临时 key、RTC 与摄像头，串行更新生成条件。最新选择可取消/绕过过时素材准备；SDK 条件更新不会并发。 |
| 异常恢复 | 素材上传失败保留当前输出，支持重试；退出、停止、到期及连接错误沿用回收与撤销确认。MoX 和模式变化不复用原摄像头会话。 |
| 后台同步 | 等待 revision 变化即返回状态，最长 8 秒；断线释放订阅，旧服务回退轮询。 |
| 可观测性 | 首帧耗时从素材准备前计时，Web 记录凭证、上传/缓存命中、RTC 和 SDK 提交阶段。会话首帧、SDK 提交和人工确认新衣服可见保持独立。 |
| 素材管理 | 卡片独立显示云端准备状态；失败给出脱敏原因和冷却后的重试入口。本地保存成功与云端已就绪分别反馈。批量查询不触发上传或生成。 |
| 准备顺序 | 每轮先处理当前选中素材，再处理已启用素材，最后处理其他素材；同优先级轮换镜子。跳过已就绪及冷却中的任务，自动准备保持单并发。 |

引用为 `.data/prepared-references/` 下的持久记录，不进入 Git；本地原图保留为恢复来源。取消人为一小时到期、周期 DNS/HEAD 和缓存续期；Decart 请求 persistent，XMAX 不设置本地到期，但不承诺供应商永久保留。只有实际供应商到期或工作人员显式重新上传才替换。业务密钥仍由现有镜端配置管理，不从其他项目复制。并发和失败冷却仅限制准备任务，不是本地累计额度限制。

## 可复现验收

```sh
npm run build
npm test -- --maxWorkers=4
npm run test:runtime
npm run test:package
cd android/exhibition
sh scripts/test-native.sh
sh scripts/build-local.sh assembleDebug lintDebug --max-workers=2
```

新增自动化检查覆盖持久引用重开、90 天直接复用、双服务自动上传、账号/区域/内容隔离、供应商硬到期迁移、STS 到期、原图 bytes/MIME、安全检查失败、网络不确定不盲目重传、HTTP 变更即时响应、Web 过时准备不阻塞最新选择、计时覆盖准备阶段，以及 Android 一次体验多轮生成、缺少发布快照拒绝启动、续接前临时失败保留健康连接、过时准备取消和最终资源清理。

模拟断言直接检查供应商替身调用次数：同模式换装只创建一次凭证和一次 RTC，准备命中跳过前台图片下载/上传，连续条件更新不会再次报告会话首帧。浏览器验收使用本地构建、假摄像头与隔离 API；真实识别 worker 与合成手势场景分别记录。

本轮按授权只做模拟供应商验收，不调用真实 XMAX key，不重新消耗 Openbuy 的供应商额度。以上能证明本地调用顺序、复用和异常恢复，不能给出 Miror 实际生成提速百分比或画面质量结论。现场仍需检查大屏摄像头、网络、SDK 远端可见换装及停止情况。代码推送与站点部署分开管理。
