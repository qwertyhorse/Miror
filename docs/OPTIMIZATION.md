# 展会素材与实时链路（2026-10-16）

管理员上传一次展示图和模型参考图，素材默认上架。后台自动向已配置且支持其模式的供应商准备持久引用；当前服务成功后，镜端自动可选。管理员操作为上传、编辑、上下架，没有手动准备、草稿发布或部分发布步骤。

## 素材与引用

| 环节 | 当前行为 |
| --- | --- |
| 保存素材 | 稳定 ID、双图、模式、元数据与内容版本分别保存，上架选择独立于供应商结果。新上传插入列表最前；已有素材和上架顺序保留。 |
| 自动上传 | XMAX 与 Decart 各自保存结果，Decart 仅准备 `clothx`；未配置或不支持跳过。备用服务失败不覆盖当前服务成功。只上传模型参考图，展示图用于列表和预览。 |
| 任务与重试 | 自动单并发，全服务最多 2 个准备任务。临时失败冷却 60 秒，每内容/账号身份最多 3 次尝试（含首次）；错误配置、拒绝或不安全输入等待处理。人工重试重置次数。失败、次数及未完成回执落盘，重启不重置预算。 |
| 引用复用 | 供应商、账号、区域、内容 SHA-256 和 MIME 相同则复用。哈希写文件时计算并缓存；统计不读取全量原图。相同内容跨镜复用须属于同账号/区域；其他账号独立准备。 |
| 引用有效期 | 不设本地 TTL，不做周期 DNS/HEAD 探活。Decart 请求 persistent 并验证无到期；供应商真实硬到期仍受约束。XMAX 无人为到期，但不承诺供应商永久保存。 |
| 更新失败 | 旧展示图和模型参考图成对继续生效；新版本准备成功后自动替换。仅编辑展示图复用参考图引用。产品状态为处理中、可用、需处理，保留「可用 · 更新处理中/更新失败」。 |

持久引用与失败回执位于运行数据的 `prepared-references/`，不进入 Git。文件保存成功、供应商引用准备完成、模型实际生成和用户看到换装效果是不同的确认阶段。

## 共享可用目录与体验所有权

服务端 `catalog` 是后台可体验数、Web、Android 与浏览器测试的共同来源。可用条件为当前镜目录、上架、当前模式、当前供应商和账号已有对应内容的成功引用。后台明确显示镜名、模式和服务；搜索和模式筛选数量另行显示。

`looks` 保留可编辑材料，`materialVersions` 保留必要版本。`activeLook` 固定本次选择；服务端另保留实际已绑定输入，条件应用确认或停止完成前，不因下架、素材更新或回收删除在用文件。目录可继续增加新素材，下一次选择使用最新可用版本。

浏览器测试读来源镜当前目录和文件，准备完成和编辑结果通过原有状态通知传播，没有复制整镜或长期冻结素材。测试保留独立相机、会话、心跳和停止所有权，不能控制物理镜会话。创建时冻结供应商账号及区域；来源作用域变化只结束该测试并提示重新打开。

## 开始、换装与停止

Web 与原生镜端提交素材 ID、`contentVersion` 及设备/体验身份，创建和条件更新由服务端一次解析并绑定引用。客户端不做 1.5 秒 ready 预查，不下载后自行上传，不在创建后重复绑定。MoX 仍下载本地参考图作为图片输入。

同模式摄像头体验保留临时凭证、RTC 和摄像头，条件请求及 SDK 更新串行执行。迟到响应不能覆盖最新意图；恢复性条件失败保留旧输出。SDK 提交结果未知时停止并对账，不重复提交可能已接受的操作。网络、素材未准备、内容版本变化和供应商拒绝分别反馈。

停止、租约、续接、controller epoch、未知签发及云端撤销确认沿用既有生命周期。端侧关闭不等于云端停止；未确认凭证继续阻止重复签发。正常续接与异常恢复分别处理，MoX 不自动重播。

状态长轮询等待 revision 变化，最长 8 秒，断线清理订阅；网络失败保留最近成功状态，旧响应不覆盖新 revision。首帧、SDK 条件提交和人工确认效果仍保持独立证据。

## 摄像头安装方向

原生镜端只保留一个安装方向，预览与模型输入共用；镜像单独处理。旧摄像头方向与 XMAX 输入方向冲突时要求一次校准，校准保存前禁止生成。预处理后预览只证明预处理结果，不能证明最终编码方向。

Web 摄像头使用原始方向，没有新增视频旋转管线；旋转安装的设备使用原生入口。现场用非正方形四角标记图，覆盖 0/90/180/270° 和镜像，核对实际编码/接收解码像素、rotation、模型宽高及显示比例。

## 升级与回退

本次配套升级 API、Web 与 Android 0.6.10（versionCode 25）。实时创建要求 `X-Miror-Protocol: 2` 和 `X-Miror-Material: catalog-v2`，旧 `binding-v1` 镜端返回 426，不签发临时凭证。Decart 另需 `X-Miror-Realtime: decart-v1`。

镜状态升级为 schema 6；原已发布项继续上架，历史未发布项保持下架，新上传默认上架。保留旧素材、引用和恢复备份；挂接连接服务前保留历史版本，不在未知账号准备状态下提前删除。旧发布 POST 返回 `MATERIAL_WORKFLOW_UPGRADE_REQUIRED`，不能借旧接口创建新发布状态。

维护窗口先停止接待与活动会话，完整备份数据库及 WAL/SHM、设备、素材和加密配置，再同步升级。回退先停止新连接，再恢复完整兼容备份，不让旧程序直接打开新数据库，不以清空未确认记录绕过停止门禁。具体 API 见 [API 文档](API.md)。

## 验证与现场边界

```sh
npm run build
npm test -- --maxWorkers=4
npm run test:runtime
npm run test:package
cd android/exhibition
sh scripts/test-native.sh
sh scripts/build-local.sh assembleDebug lintDebug --max-workers=2
```

关键回归覆盖上传自动可用、双供应商独立结果、替换失败保留成对旧版本、展示图编辑不重传、跨镜/模式/账号隔离、已打开测试跟随目录、重启与迁移保留版本、有界自动重试与人工重试、上下架保留在用会话、迟到响应、未知签发和同连接多次换装。

供应商替身检查凭证/RTC 创建次数、引用复用、SDK 条件串行更新和资源清理；本地构建、假摄像头和隔离 API 可验证调用顺序与生命周期。模型首帧和条件 ack 均不能替代实际换装可见性。现场还需两台实际 Android/USB 摄像头的方向、网络、远端画面、真实供应商效果、停止与长时运行记录；本地模拟不声明这些已通过，也不推导实际提速百分比。
